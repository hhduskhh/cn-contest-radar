# 国内计算机 / AI 赛事信息聚合

自动聚合国内计算机与 AI 类赛事信息（蓝桥杯、CCPC、码蹄杯、天池、CCF BDCI 等），
每周定时爬取一次，也可以在网页上手动触发。核心产出是**历年赛事时间线** ——
把每个赛事各届的报名时间与比赛时间画在同一张图上看节奏，方便安排备赛。

## 快速开始

```bash
# 1. 安装依赖
python -m pip install -r requirements.txt

# 2. 准备配置（把 .env.example 复制为 .env，改掉密码）
cp .env.example .env

# 3. 启动
python run.py
```

启动后终端会打印本机与局域网的访问地址。手机连同一个 WiFi 就能打开
`http://<你的内网IP>:8000/`，会先弹出账号密码框（就是 `.env` 里那对）。

首次启动建议手动跑一次**全量**爬取（见下方「爬取模式」），把历史数据抓下来。

## 功能

| 页面 | 内容 |
|---|---|
| **总览** | 「近期节点」红榜（未来 120 天内的报名截止与开赛，按紧迫度排序）+ 全部赛事卡片 |
| **历年时间线** | 每年一行、横轴 12 个月，两条色条分别是报名期与比赛期。跨年的区间会断开并在下一年继续，把「10 月报名、次年 4 月比赛」这种节奏直接画出来 |
| **数据源** | 各源健康状态（上次成功时间、连续失败次数、最近错误）+ 历史爬取批次 |
| **赛事详情** | 单个赛事的历届记录表 + 已抓到的相关通知 |

右下角的**「立即爬取」**按钮在任何页面都能点，会弹出实时进度（每个源的状态、
耗时、新增条数、错误）。手机上游览页面刷新后，如果后台还有任务在跑，会自动接续显示进度。

### 关于地域

**默认展示全部赛事，不做地域过滤。** 判断标准是「能不能在广东参加」，而不是
「比赛地在不在广东」—— CCPC 分站赛决赛虽然在哈尔滨、济南，但初赛（网络赛）
是线上的，广东的学生照样能参加。

每条记录都标了参赛方式：

| 标注 | 含义 |
|---|---|
| 线上参加 | 全程线上，无举办地。赛事库里绝大多数属于这类 |
| 广东线下 | 赛场在广东省内（如 CCPC 2023 深圳站、ICPC 2026 深圳站）|
| 需出省 | 决赛在外省，但初赛可线上参加 |

右上角的「**隐藏需出省的**」开关可以临时把第三类收起来（537 → 503 条）。
默认关闭。

### 链接

每条记录都保留了原始网址，点一下直接跳官网：

- 赛事卡片右上角的「官网 ↗」→ 赛事官网首页
- 时间线上的色条 → 该届数据的来源页面（原文通知或赛程表）
- 赛事详情页的「来源」列 → 同上
- 相关通知列表 → 通知原文

537 条届次记录全部有可点击来源，没有缺失。

### 两类赛事，两种粒度

这个区别很重要，决定了时间线怎么画：

- **系列赛事**（蓝桥杯、CCPC、ICPC、天梯赛、码蹄杯、4C、睿抗、大数据挑战赛）——
  一年一届，届内再分赛站/赛道。时间线上**一届一条泳道**，能看出跨年节奏。
- **平台赛事**（天池、讯飞、AI Studio、DataFountain、和鲸）—— 一个平台一年办上百场
  互相独立的比赛。时间线上**按年聚合成一条**（标注该年有多少场），否则会出现几百条
  泳道完全没法看；但在总览和赛事详情里，每一场都是独立一条，各自的报名截止时间不会丢。

另有**人工整理的历年数据**（`data/seeds/editions.json`），覆盖 2021–2026 年
蓝桥杯、天梯赛、码蹄杯、大数据挑战赛、CCF BDCI、睿抗、计算机设计大赛、讯飞大赛。
每条都带来源 URL 和整理说明，在时间线上用斜纹填充与爬取数据区分开。

### 关于讯飞（已解决，无需登录）

讯飞的接口**无需登录**，一次返回全部 667 条赛事（2019–2026 每年约 100 条），
且带完整的分阶段时间：报名开始/截止、初赛开始/结束、复赛结束、决赛开始/结束。
这是所有数据源里时间信息最全的一个。

```
https://challenge.xfyun.cn/2020/ai-contest/api/contests/contests-list
```

三个踩过的坑，都写在 `app/crawlers/xfyun.py` 的模块注释里：

1. **路径必须有 `/contests/` 这一段。** 少了它（`/api/contests-list`）会返回
   `{"flag":false,"code":10008,"desc":"请求方法或类型不支持"}` —— 看起来像是接口废弃了、
   需要登录，实际只是路径不对。这个误区一度让这个源被误判为不可用。
2. **`contest_name` 是数字 ID 不是名称**，真正的名称在 `name_basic_problem`。
3. **`1999-09-09` 是哨兵值**，表示「该阶段不存在」（519 条用它表示无复赛）。
   不过滤的话时间线上会凭空多出 1999 年的赛事。

代码里仍保留了 Cookie 配置入口（`data/runtime.json` + `/api/admin/credential`）
作为备用 —— 万一将来讯飞真的改成需要登录，可以直接用上，不必重写。平时用不到。

## 爬取模式

| 模式 | 行为 | 用在哪 |
|---|---|---|
| `incremental`（增量） | 连续几页都是已知条目就提前停止翻页。日常用这个 | 每周定时任务、手动按钮 |
| `backfill`（全量） | 翻到底，抓全部历史 | 首次部署时跑一次 |

全量模式会向天池和 AI Studio 各发约 60 次请求，**建议在夜间手动跑一次**，
之后走增量就行。

每周定时任务默认在周一 03:17（可在 `.env` 里改 `CRAWL_CRON_*`）。
调度触发与手动触发走的是完全相同的代码路径，只在批次记录的 `trigger` 字段上区分。

## 数据可信度

时间线上每条记录都标了来源与置信度，鼠标悬停可以看到**原始文本**（如通知里写的
「报名时间：9月1日-9月15日」），方便自己核对：

- **置信度高** — 来自接口的结构化时间字段
- **置信度中** — 来自结构化页面，或官方赛程表
- **置信度低** — 从通知正文正则抽取，可能不准确

人工整理的条目会单独标注，并附整理说明（比如「官方只公布到旬，此处填的是区间边界」）。
**抽不到时间的记录不会被丢弃**，而是显示为「时间待公布」—— 这本身也是有用的信息
（说明该届已启动但赛程未出）。

## 项目结构

```
app/
  crawlers/          八个数据源，各自独立
  pipeline/          归一化、关键词抽取、落库、编排
  api/               HTTP 接口
  nuxt.py            Nuxt SSR 页面的数据解析器
  seeds.py           种子数据导入
web/                 前端（原生 JS，无构建步骤）
data/seeds/          赛事目录与人工整理的历年数据
scripts/             一次性工具
```

数据库是 SQLite（`data/app.db`），时间统一以 UTC 存储、按北京时间展示。

## 常见问题

**手机连不上？** 先确认同一个 WiFi，然后检查 Windows 防火墙是否放行 8000 端口
（首次运行 Python 时会弹窗询问，容易误点「取消」）。可以先用手机浏览器访问
`http://<内网IP>:8000/healthz` 测试，这个路径不需要登录。

**某个源标红了？** 数据源站点的接口生命周期普遍很短，改版就会失效。
原始响应都完整保存在 `source_items.raw_json` 里，改版后**只需修改解析层、
用历史数据回放重解析**，不必重新抓取。

**想加新赛事？** 在 `data/seeds/events.json` 里加一条（含 slug、名称、别名），
重启或调用 `POST /api/admin/reload-seeds` 即可。别名用于把通知标题匹配到赛事，
多命中时取最长别名。

**手动爬取按钮没反应？** 如果已有任务在跑，按钮会接续显示那个任务的进度而不是报错
（手机和电脑同时打开时很常见）。看右下角抽屉里的进度即可。

## 安全说明

- 服务绑定 `0.0.0.0` 且使用 HTTP Basic 鉴权。**仅适用于局域网，绝不要暴露到公网** ——
  Basic 凭据是明文传输的。
- 密码从 `.env` 读取，`.env` 与 `data/runtime.json` 都在 `.gitignore` 里。
- 讯飞 Cookie 只存服务端，任何接口**都不会回传它的明文**，界面只能看到「已配置/未配置」。
- 爬取频率保守：同域请求最小间隔 1.5 秒，全局并发不超过 3，超时 10/30 秒，
  失败指数退避重试 3 次。所有已接入的接口都是匿名公开的。
